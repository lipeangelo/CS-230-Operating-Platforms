# CS 230: Operating Platforms

## The Gaming Room — Draw It or Lose It

### Project Overview

This project was completed for CS 230: Operating Platforms at Southern New Hampshire University. The project involved creating a software design document for The Gaming Room to support the expansion of its game, *Draw It or Lose It*, from Android to a web-based application accessible across multiple operating systems.

### 1. Briefly summarize The Gaming Room client and their software requirements.

The Gaming Room wanted to expand its multiplayer drawing and guessing game, *Draw It or Lose It*, to support Windows, macOS, Linux, and mobile devices. The application needed to support multiple games, teams, and players while maintaining unique identifiers and preventing duplicate names. The client also required a scalable, secure, and reliable application.

### 2. What did you do particularly well in developing this documentation?

I believe I did particularly well in organizing the software requirements and evaluating different operating platforms. Comparing Linux, Windows, macOS, and mobile environments helped me identify their advantages and limitations. I also developed recommendations for the application's architecture, memory management, storage, networking, and security.

### 3. What about the process of working through a design document did you find helpful when developing the code?

The design document helped me understand the application's requirements before implementing the code. Creating the UML class diagram clarified the relationships between GameService, Game, Team, and Player. This made it easier to apply object-oriented programming principles such as inheritance and encapsulation, along with the Singleton and Iterator design patterns.

### 4. If you could choose one part of your work on these documents to revise, what would you pick? How would you improve it?

I would improve the system architecture section by adding a detailed diagram showing how the client applications, Linux server, database, and network services communicate. This would provide a clearer representation of the system and help developers understand the relationships between its components.

### 5. How did you interpret the user's needs and implement them into your software design? Why is it so important to consider the user's needs when designing?

I translated the client's requirements into specific design decisions, including unique identifiers, centralized game management, and cross-platform compatibility. I recommended a Linux-based server with a browser-based interface to improve accessibility and scalability. Considering user needs is essential because it ensures the application solves the intended problems while remaining reliable and maintainable.

### 6. How did you approach designing software? What techniques or strategies would you use in the future?

I approached software design by identifying requirements, creating a UML class diagram, implementing the core Java classes, and evaluating different operating platforms. I also considered how memory, storage, security, and networking would affect the application. In future projects, I would continue using UML diagrams, object-oriented design principles, and design patterns while incorporating early prototyping and testing to identify potential issues.
